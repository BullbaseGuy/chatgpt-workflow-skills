# ADR-0001: Separate the Skills Source from the Project Scaffold

- **Status:** Accepted
- **Date:** 2026-08-03

## Context

Cross-project skills need one authoritative home. `BullbaseGuy/demo-project` already acts as a
generic repository scaffold. Copying skill bodies into every generated project would create
drift, duplicate maintenance, and ambiguous authority.

The decision is hard to reverse after many projects adopt the system, is surprising without
context, and reflects a real trade-off between self-contained repositories and centralized
maintenance.

## Decision

`BullbaseGuy/chatgpt-workflow-skills` is the sole source of reusable skills, shared references,
templates, validation scenarios, and installation logic.

`BullbaseGuy/demo-project` remains the engineering scaffold. It may contain:

- a minimal router pointer;
- a pinned skills-source revision or release;
- installation/upgrade workflows;
- repository-specific task state and product gates.

It must not copy and independently maintain the skill bodies.

## Consequences

- Skill corrections are made once and distributed through a pinned install or update path.
- Consumer repositories remain smaller and can audit exactly which release they use.
- An unavailable skills source can affect fresh installation, so consumers must pin a version
  and retain a locally installed copy generated by the installer.
- Compatibility between scaffold and skill releases must be tested explicitly.
